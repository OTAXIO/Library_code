# 机构知识库助手 0.4.33

0.4.33 仅更新桌面脚本，**扩展仍为 0.4.31，不需要再重载**。关闭旧助手后重新启动即可；关机或长时间未使用后，先确认现有 SA、后台导入页已登录，再连接当前桌面配对码。

- 每轮在 `runtime/run-reports/` 保存独立诊断：任务、当前阶段、命令是否返回、实际批次计数、失败原因和代码位置。失败时窗口显示文件位置；`log.txt` 仍只保留最近 **100 次操作**，增加暂停/跳过的具体原因，不按行截断。报告不保存文件内容、请求头、Cookie 或配对码，也不代替入库断点。
- 数据源错误明确区分 Crossref/OpenAlex、超时、权限、限流、证书及响应格式；连接失败不记为未收录，不自动重复请求或导入。Excel 运行库的原始错误另保存在同篇归档目录 `excel-build.log`，不再只显示一个笼统的生成失败。
- 元数据缓存改为原子、排他保存，可恢复中断后遗留的空目录；已有损坏、错编号或内容改变的证据保留并暂停，不覆盖。题名只兼容 HTML、引号、连接号和句末点号等格式差异；实质词语、数字或 DOI 不一致仍拒绝自动入库。
- Windows 暂时占用名单时，仅对已核验临时文件的本地原子替换最多尝试三次。每次重查原文件指纹及 Excel 占用；不会重发网页导入，也不会覆盖期间发生的人工修改。
- Windows 复制配对码先直接传递 Unicode 内容，仅在剪贴板短暂被占用时有界等待；失败显示真实原因，不假报成功。本次排查确认受限沙盒启动的窗口会被 Windows 拒绝访问剪贴板，正常桌面启动已通过实际复制按钮自检。使用 `启动助手.vbs` 启动，不需要反复重载扩展或重新配对。
- 跳过结果在本轮摘要直接显示具体原因和条数，不再把仅修改名单的跳过结果写成“网页与名单已同步”。每条事实及完整诊断仍保存在本机。

真实名单、诊断报告、缓存和运行日志只保存在本机，不提交 Git。

0.4.32 仅更新桌面编排，**现有扩展 0.4.31 不用重载**。后台明确返回“已推送、成功一条、新增零、重复一条”时，保留实际批次，名单记“本库重复待核验”/2，继续下一篇；不能把它算作新增或提交认领/结案。计数不完整、互相矛盾或回执未知仍暂停，不清空断点。显式重试该类项也只读复核，不重新上传或推送。

0.4.31 修复跳过一篇后被旧详情窗口挡住：自动队列读完本条详情会通过原生关闭生命周期收起它，再继续下一篇；普通人工查看不变。旧版已入库但待核验的明确断点仅做只读窗口恢复，不重新上传、认领、结案或清空跳过标记。编辑、未保存认领选择及其他弹窗仍拒绝自动关闭。

0.4.30 集中修复批量中断和完成判断：已确认入库后的作者/第一单位分歧仅将该篇标为待核验并继续，保留原批次断点、不认领或结案；未知提交结果仍停止，不能被“后台已处理”掩盖。批次模型和结案前作者/单位/匹配数都独立核对。新增会议模型与上传前必填检查，会议论文不能按期刊模型提交。

关联/认领后，后台可能自动变为“已处理”。本次确认为新增的两源入库仍会补写“已入库”，但保持已处理，不点击会反转状态的原生按钮。只允许本条已核验批次、平台关联、已认领及一致角色/单位；人工备注、其他条目和未知写入意图均不覆盖。已有“已入库”只回读，不再提交。

两个功能：**自动认领**、**自动导入**。新增默认的 Crossref＋OpenAlex 通用 Excel 导入；原 WOS 自动/手动导出导入均保留。生产网页操作固定使用本库扩展与桌面 Bridge，Browser Skill 仅供开发验收，不是脚本依赖。

## 推荐：不经过 WOS 的 Excel 导入

1. 启动助手，选择谭勋策、待处理、本轮 1–5 条，在“自动导入”选择 **Crossref＋OpenAlex（Excel）**。
2. 重载扩展 **0.4.31**，连接已有 SA 比对页，绑定已有后台“数据导入与批次管理”页；此模式不需要 WOS 或 WOS 下载权限。
3. 点击“开始自动导入”。只处理当前负责人为谭勋策、名单和后台均为未完成零匹配的任务；普通批次跳过末列为 2 的记录。
4. 脚本按 DOI（缺 DOI 时只接受唯一精确题名）获取 Crossref 数据，再用 OpenAlex 同 DOI、同题名、同顺序的原始作者与署名单位核验。期刊要求 `journal-article` 与 `article/review` 一致，会议要求 `proceedings-article` 与 `conference-paper` 一致、真实会议名称和原始交大署名完整；分别选择原生“期刊论文/会议论文”模型。缺会议日期不填造，会议录信息不唯一不猜选。其他类型仍搁置；不推断通讯作者、第一作者、本校第一单位或 WOS 收录号。
5. 每篇在 `runtime/metadata-imports/papers/` 保存原始两源 JSON、可核验单篇 Excel、哈希与预览。只读取该归档 Excel 上传，绝不从 Downloads 随便选文件。后台使用实际来源 **人工提交**，list 的“数据来源”写 **Crossref+OpenAlex**，不冒充 WOS。
6. 本库 DOI 与完整题名查重后才上传；按照原 PPT 机构、说明与推送规则，确认批次恰好 1 篇、失败 0、推送完成及平台唯一号。关联后若未认领，按 SA 工号查唯一人员、精确匹配署名，认领并回读；不推断或更改作者角色，角色/第一单位不一致时保留断点等待核验。确认认领后，网页备注 **已入库**并设为**已处理**；读回成功后，list 首列备注 **已入库**，末列“是否识别”写 **1**。

不会仅凭 OpenAlex 的机构归一化结果判交大；必须有作者对应的原始署名单位。缺少交大证据记“未确认交大署名”，不伪称“非交大”。Crossref/OpenAlex 未查询到也不写“wos未收录”。已经在本库存在的论文不重复入库，本模式先跳过，不冒充本次新入库；原自动认领功能保留。

需要 Python 原依赖，以及可用的 Node 与 `@oai/artifact-tool`。默认识别本机捆绑运行库；独立部署可配置 `SA_NODE_EXECUTABLE`、`SA_ARTIFACT_NODE_MODULES`，后者指向含 `@oai/artifact-tool` 的 node_modules。缺失运行库时会在上传前明确停止。公开 API 基本使用不需要密钥；不自动注册账户或启用付费服务。接口依据：[Crossref REST](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)、[OpenAlex API](https://help.openalex.org/api/)、[原始作者及署名单位](https://help.openalex.org/data/authorships/)。

断点独立保存在 `runtime/metadata-imports/zero-match.sqlite3`。回执不明时只读续验；上传中断可接回尚在本页、SHA-256 与名单完全对应的原上传窗口。不要刷新未提交的 Excel 向导，不要删除断点来“强行重试”；跨 WOS/Excel 模式不能绕过已有写入断点。两源 JSON、名单、Excel、日志及本地验收配对记录均不提交 Git。

维护与恢复的模块边界见 [WORKFLOW.md](WORKFLOW.md)。

1. 将最新名单放在本目录，命名为 `list.xlsx`。关闭正在编辑它的 Excel。
2. 双击 `启动助手.vbs`。负责人选择谭勋策，本轮条数先设为 1–5。
3. Edge 的 `edge://extensions` 重载本目录 `extension` 中的“SA 比对半自动助手”，版本应为 **0.4.31**。没有未完成上传窗口时再刷新已有工作页。恢复原导出或 Excel 上传断点时保留对应页面，不重复提交。

## 手动跳过一条

在“自动认领”或“自动导入”的“待处理”范围内选中一条，点击“跳过所选数据”并确认。只将所选谭勋策记录的末列“是否识别”写为数字 2，保留所有现有备注和数据来源；不认领、不导入、不在网页结案。保存前备份，普通批次不再执行该条；之后可在“重试跳过项”中处理。无需浏览器在线，也不重试失败的后台查询。

运行中、已完成、已跳过、多选、其他负责人或名单被修改时不能跳过。有上传/导入/推送/关联/结案断点待核验的记录也不能强行跳过，须先续验原操作，断点不删除。

“名单 ID 未返回唯一结果”表示 SA 后台按名单编号未返回唯一一条，不等于 WOS 没有文献。该条尚未入库时可以手动搁置，再开始下一批；不会把这个错误记成“wos未收录”。

## 自动认领

选择“自动认领”，范围为“待处理”，点“开始自动认领”。只处理谭勋策的单匹配作者认领任务及 DOI/WOSID 双缺失认领任务。

先检查后台处理状态。已处理的仅同步名单；未处理的按 SA 括号编号查唯一人员，再用其已存在的姓名/别名匹配唯一署名。不猜作者、不覆盖别人认领、不自动新增别名。

认领成功回读后填写网页批注，再结案和回写名单。作者不一致使用“已认领”；SA 确认双标识未提交时使用“DOI和WOSID SA未提交；已认领”。无法唯一识别人员、无认领窗口等标为跳过并保存真实原因。

## 手动导出，一篇入库（导出不稳定时使用）

1. 打开“自动导入”，导入方式选择“手动导出（一次一篇）”，在列表中选中一篇。此模式不使用本轮批量条数，也不自动选择下一篇。
2. 点“① 定位 WOS 文献”。脚本只检索并打开对应单篇，不点最终 Export，也不提交入库。
3. 在 WOS 手动选择 Export → Tab delimited file → Full Record → Export，等待 TXT 下载完成。已有正确的同篇 TXT 时可以直接执行下一步。
4. 点“② 接回 TXT 并入库”。脚本按内容与定位的入藏号对应文件，核验并复制到 code，再查重、上传、导入、按 PPT 推送、精确关联平台号，回读后网页备注“已入库”并结案，名单备注“已入库”、是否识别 1。

等待手动导出时不写 1/2、不填失败备注，也不会自动 Search 或 Export。第二步只处理当前选中的这一篇；TXT 缺失、内容不同、题名/DOI/WOS 冲突时不会随便选择文件。确认非交大仍按原规则备注“非交大”并结案，不入库；未查询到、作者/单位判断待核验及非零匹配沿用原规则。导入、推送或结案回执未知保留意图，只读续验，不重复提交。

## 原 WOS 自动导入（可选）

选择“自动导入”，点“开始自动导入”。范围来自当前负责人名单中的 **未完成、匹配数为零**记录，无需先做 AI 分类，也无需分别按“下载”“检查”“导入”按钮。

程序按顺序执行：后台状态检查 → WOS 检索 → 导出 Full Record TXT → 文件身份和交大署名核验 → 本库查重 → 必要时上传/导入/推送 → 关联平台号 → 网页批注及结案 → 名单回写。

**当前入库结案规则：**本条确实新增入库并推送成功、同篇平台号关联成功、精确认领及作者/单位核验通过后，再只读核验对应批次新增 1、失败 0、重复覆盖 0，网页备注精确写“已入库”并设为已处理；回读确认后 list 首列也写“已入库”，末列“是否识别”写 1。作者或第一单位分歧保留入库断点并搁置，不推断或擅自更改。下载完成、上传成功、提交导入或未知回执不能冒充全部结案完成。

推送遵循 PPT：查重“是”，唯一标识及期刊/发表时间/页码/卷期/题名相似度的指定组合，重复元数据“根据优先级合并”，不存在条目“新增”，本校成果“是”。机构为上海交通大学，说明为 `SA补充-名单ID`。

若本库已经有完全对应的唯一文献且不是本条已核验的入库断点，关联已有平台号、不重复上传，原有必要时认领和详情核验流程保留，不伪称本条新入库。TXT 和进度日志按名单编号、事实指纹、文件 SHA-256 对应，不采用下载目录中的“最新文件”。

0.4.8 的结果导航直接点击网页中已经核验的唯一论文标题链接，不用 `tabs.update` 重载单篇网址，以保留 WOS 自身的检索上下文。点击前再次确认总数 1、无加载/弹窗、唯一同源入藏号和目标未变化；不打开新标签。链接点击回执不明时不会再点击，也不会改用网址跳转兜底。仅“总数为 1、无加载、缺少链接”的读数可在 MAIN 环境用同一个 DOM 只读函数交叉核验；冲突不能放行。

0.4.6 起，已有导出断点会先按其题名、入藏号及所有已填 DOI/WOS 接回本地完整 TXT，即使工作页已切回检索页也不会重复导出。仅题名记录可接回同一检索断点的文件，但仍不因此获得自动入库或非交大结案权限；首次关联仍须强标识。执行器本身也拒绝在普通待处理批次执行是否识别为 2 的任务，不只依赖界面筛选。

程序先检查当前用户的 `Downloads` 中已完成的 `savedrecs.txt` / `savedrecs (数字).txt` 等 WOS 导出。必须题名完全对应、至少一个名单 DOI/WOS 强标识相同且所有已填标识不冲突；续接导出还要求 TXT 入藏号与当次检索单篇网址一致。不满足条件的文件不能自动归到当前论文。多个同篇文件内容不同会暂停核验，不按日期猜选。

找到同篇已下载文件时直接核验和复制，无需再搜或导出。否则 WOS 唯一结果进入单篇页后分两步操作：打开 **Tab delimited file → Full Record** 预览，再点击弹窗内最终 **Export**。Full Record 已选中时不重复打开下拉框。只有最终 Export 尚未提交的准备阶段能对白屏单篇页刷新一次并等待恢复；登录/验证码、网站 5xx、无关弹窗不能靠刷新绕过。

最终 Export 前先保存断点。若回执超时，先核查本地同篇 TXT；没有文件则保留导出意图。只有原页面的本条“尚未点击最终 Export”回执能续提交，已点击或结果不明不会重新点击。明确收到插件点击前路径拒绝的回执时则退回准备阶段、保留该回执；准备阶段网页被刷新或切回检索页，最多重新检索一次并要求与旧断点同一 UT，再打开预览。未知/已提交断点不能这样重新检索或导出。人工下载完成后从同一入口继续，脚本会按内容接回。

核验后的副本在 `runtime/wos-downloads/按名单编号/`，文件名为 `名单ID__WOS-入藏号__哈希前12位.txt`；旁边 JSON 记录名单事实指纹、DOI、WOS号、完整哈希和单位证据。下载原件不删除、不移动、不覆盖。上传仍使用经过完整哈希核验的存档字节，不信任文件名；下载成功本身不表示允许入库或名单完成。

**上传只读取 code 内存档：**队列先将核验后的完整 TXT 复制到 `code/runtime/wos-downloads`，入库再使用 `code/runtime/wos-imports` 的同一 SHA-256 字节；不会直接把下载目录的“最新 TXT”传入系统。已有对应存档直接复用，同 DOI/WOS 的历史写入意图会阻止重复入库。

若当次检索入藏号对应的 TXT 已下载，但题名或名单标识冲突，保留在 `runtime/wos-downloads/未关联下载`，不建立名单关联、更不上传；首列记录“题名待核验”或“标识待核验”，末列写 2，继续下一条。其断点记录为已下载但未关联，再次检查只读存档、不会重新点击 Export。不同入藏号、内容不同的同篇导出、未知提交结果仍暂停，不能假装成某篇零结果或非交大。

另有独立整理脚本，**无需日常手动运行，自动导入已集成本地接回**：

```powershell
# 默认只预览，不写文件
python .\wos_files.py
# 复制有效单篇 TXT 到 runtime/wos-downloads/未关联下载，保留下载原件
python .\wos_files.py --apply
```

这条独立命令不读写 Excel、不提交后台，也不自动编造名单对应关系；未关联副本要经过队列的强标识匹配和交大署名核验才能进入入库流程。`--source-dir` 可指定其他实际下载文件夹。

## 范围和结果

- 本轮条数 1–100，按名单记录计数。同一论文可复用一个真实 TXT，但每个 SA 编号单独关联、认领和结案。
- “待处理”不执行已完成或已跳过记录；“重试跳过项”仅执行末尾“是否识别”为 2 的记录；“已完成”只供查看，开始按钮禁用。
- 导入前发现本条已有非零匹配：仅在末尾“是否识别”写 2，**不新增、覆盖或清空任何备注，也不改网页处理状态**，随后继续下一条；匹配数未知时暂停、不猜成非零。脚本本身已核验入库并精确关联后的 0→1，以及有本条持久关联断点的续验仍正常结案，不能将已成功入库的记录误标为跳过。
- 上一轮 Export 断点与当前搜索框内容无关。先接回存档、已保存的实际下载路径，或浏览器中同一入藏号的下载记录；接回后仍逐项核验 TXT。浏览器确认空闲、无在途下载且完整查找仍没有文件时，仅本条备注“下载待核验”及末列 2，保留导出断点并继续下一篇，不当作“wos未收录”，不重复 Export。登录、验证、通信断开或仍在途的下载继续安全暂停。
- 浏览器返回 TXT 下载成功后，先持久保存路径再解析和存档。自定义下载目录也能从原路径续验；上传仍只读取 code 内经过校验的副本，不按“最新下载”选择文件。
- 绿色已完成，黄色待处理，红色已跳过。首个“备注”列写文字，末尾“是否识别”写 1/2，另记“数据来源”。
- 完成必须有网页状态及批注回读，下载或推送成功本身不等于结案。网页原已处理项使用后台实际批注同步名单。
- 明确非交大：必须 TXT 与本条 SA 获得题名＋DOI/WOS 强匹配，全部作者均有完整单位记录且没有交大署名。只在仍未处理、零匹配、没有其他网页备注的本条写“非交大”并设为已处理；回读成功后名单备注同为“非交大”、“是否识别”写 1，数据来源记 WOS，随后继续下一条。**这表示任务结案，不表示文献入库；不会上传、推送、关联或认领该非交大文献。**
- 非交大结案前保存独立写入意图；回执丢失只读续验，不能再次提交。旧扩展缺少结案协议时在提交前停止，需重载当前版本。
- WOS 已确认的真实零结果在首个“备注”列写“wos未收录”，末尾“是否识别”写 2，继续下一篇。这是用户指定的检索结果备注，不代表已证明数据库从未收录。超时、缺少控件或链接不能标成零结果。只有题名匹配、没有 DOI/WOS 强标识，或作者单位证据不完整的仍保留待核验/跳过，不猜测同一论文，也不因未见交大字样直接结案。
- 自动认领、首次入库前或关联已有文献时，需要判断第一作者、通讯作者、第一单位等的仍先跳过，不自动改角色。本条已核验入库成功时，按上面的“已入库”规则结案，不将结案解释成作者认领完成。登录/验证码、通信断开或写入结果不明暂停整批，未执行尾部不写成跳过。
- 名单跳过原因用简短标签，如“第一单位待核验”“作者编号待核验”“认领对象待核验”；完整诊断保存到私有结果报告及最近 100 次操作日志。备注简化不更改完成状态。清理历史下载/导入失败须另行明确选择目标和校验候选名单，不能在启动或普通重试时自动清空 2。

点击“暂停”后等待当前回读结束再关闭。超时提示出现时先核验网页，不连续点开始。恢复使用同一入口，已有上传/导入/推送意图会只读续验，不盲目重复提交。

运行时扩展会自动切换到已经绑定并校验过的工作标签页，避免后台网页计时器被限流。请不要同时在这些页面手动操作。

## 保存与恢复

- `log.txt` 保留最近 100 次操作，不是 100 行。
- `runtime/wos-downloads` 保存真实 TXT；`runtime/wos-imports` 保留入库及补录断点。旧资料和密钥没有删除，但旧 AI 页面已退出程序。
- 名单窄范围 XML 回写前备份、校验文件指纹并在保存后重读。不要在程序运行时编辑名单。
- 旧功能源码可从 Git 提交 `b1f812c` 或 `runtime/checkpoints/2026-10-10-minimal/pre-simplify-b1f812c.bundle` 恢复。
