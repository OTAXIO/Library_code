0.4.6 起，已有导出断点会先按其题名、入藏号及所有已填 DOI/WOS 接回本地完整 TXT，即使工作页已切回检索页也不会重复导出。仅题名记录可接回同一检索断点的文件，但仍不因此获得自动入库或非交大结案权限；首次关联仍须强标识。执行器本身也拒绝在普通待处理批次执行是否识别为 2 的任务，不只依赖界面筛选。

程序先检查当前用户的 `Downloads` 中已完成的 `savedrecs.txt` / `savedrecs (数字).txt` 等 WOS 导出。必须题名完全对应、至少一个名单 DOI/WOS 强标识相同且所有已填标识不冲突；续接导出还要求 TXT 入藏号与当次检索单篇网址一致。不满足条件的文件不能自动归到当前论文。多个同篇文件内容不同会暂停核验，不按日期猜选。

找到同篇已下载文件时直接核验和复制，无需再搜或导出。否则 WOS 唯一结果进入单篇页后分两步操作：打开 **Tab delimited file → Full Record** 预览，再点击弹窗内最终 **Export**。Full Record 已选中时不重复打开下拉框。只有最终 Export 尚未提交的准备阶段能对白屏单篇页刷新一次并等待恢复；登录/验证码、网站 5xx、无关弹窗不能靠刷新绕过。

最终 Export 前先保存断点。若回执超时，先核查本地同篇 TXT；没有文件则保留导出意图。只有原页面的本条“尚未点击最终 Export”回执能续提交，已点击或结果不明不会重新点击。明确收到插件点击前路径拒绝的回执时则退回准备阶段、保留该回执；准备阶段网页被刷新或切回检索页，最多重新检索一次并要求与旧断点同一 UT，再打开预览。未知/已提交断点不能这样重新检索或导出。人工下载完成后从同一入口继续，脚本会按内容接回。

核验后的副本在 `runtime/wos-downloads/按名单编号/`，文件名为 `名单ID__WOS-入藏号__哈希前12位.txt`；旁边 JSON 记录名单事实指纹、DOI、WOS号、完整哈希和单位证据。下载原件不删除、不移动、不覆盖。上传仍使用经过完整哈希核验的存档字节，不信任文件名；下载成功本身不表示允许入库或名单完成。

**上传只读取 code 内存档：**队列先将核验后的完整 TXT 复制到 `code/runtime/wos-downloads`，入库再使用 `code/runtime/wos-imports` 的同一 SHA-256 字节；不会直接把下载目录的“最新 TXT”传入系统。已有对应存档直接复用，同 DOI/WOS 的历史写入意图会阻止重复入库。

若当次检索入藏号对应的 TXT 已下载，但题名或名单标识冲突，保留在 `runtime/wos-downloads/未关联下载`，不建立名单关联、更不上传；首列记录“题名待核验”或“标识待核验”，末列写 2，继续下一条。其断点记录为已下载但未关联，再次检查只读存档、不会重新点击 Export。不同入藏号、内容不同的同篇导出、未知提交结果仍暂停，不能假装成某篇零结果或非交大。

另有独立整理脚本，**无需日常手动运行，自动导入已集成本地接回**：

```powershell
# 默认只预览，不写文件
python .\wos_files.py
# 复制有效单篇 TXT 到 runtime/wos-downloads/未关联下载，保留下载原件
python .\wos_files.py --apply
```

这条独立命令不读写 Excel、不提交后台，也不自动编造名单对应关系；未关联副本要经过队列的强标识匹配和交大署名核验才能进入入库流程。`--source-dir` 可指定其他实际下载文件夹。
