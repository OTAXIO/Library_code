# 机构知识库 · 比对助手

当前版本（2026-09-25，扩展 0.3.8）使用**人工审批完成**，支持自动判断处理路径、单条 WOS 元数据导出/导入/推送、作者认领和交大模型辅助核对。暂不处理 PDF。窗口默认置顶，约 560×700，可缩小到 520×600。上方「人工处理／自动化／模型辅助」是功能页；任务列表上方「未完成／已完成」切换列表。只有点击按钮才操作网页，不自动审批或处理下一条。另有「预检前100条」只读核验固定范围；仅对后台已处理项同步本地 Excel。

**现场验收边界：**新 WOS 流程已实现并在合成页面测试，尚未在用户已登录的 WOS/后台完成首条生产验收。页面布局、授权或下载格式不兼容时会暂停，不能将离线通过理解为已向真实库成功导入。

## 开始使用

1. **先退出旧版助手**，再双击 `启动助手.vbs`。只管理本地进度时不需要配对；要直接打开对应网页位置，请按下面的「连接浏览器」步骤配对。
2. 名单固定放在本目录，名称为 **`list.xlsx`**。Windows 隐藏扩展名时显示 `list`；不要命名成 `list.xlsx.xlsx`，不支持 `.xls`。程序不扫描其他文件或父目录。
3. 选择负责人，默认列出未完成任务。点击黄色「未完成」或绿色「已完成」切换列表；只显示当前负责人的对应任务。
4. 选中一条，点「定位网页」，在已配对标签页按完整名单 ID 搜索并打开对应详情。需要手动修改或认领时，再点「编辑」或「认领」打开窗口，由你在网页操作并保存。「ID」复制名单 ID；「SA 编号」复制网页认领状态里 SA 提交括号内的编号。自动认领见下节。完整编号与说明在「指引」。
5. 可选择备注模板，点「复制备注」，在网页中手动粘贴并保存。这里的文字不会自动写入网页。
6. 自行核实网页操作全部完成后，勾选「我已核对当前记录，并完成网页处理」，绿色「✓ 批准完成」按钮才可用。点击后核对弹窗中的 ID 并确认。
7. 保存成功后，该行的完成备注写成**数字 1**，从待办移除；当前卡片保留绿色「已完成」。可以切到「已完成」查看。已完成项可定位网页，但不能重复批准，也不能从本助手直接打开其编辑／认领窗口。需要继续时再点「下一条」，不会自动跳转或搜索。

完整阅读长题名时可滚动详情；窗口可拖动、调整尺寸或最小化。窗口置顶不会反复抢夺键盘焦点。

## 连接浏览器（可选）

1. 在 Chrome 或 Edge 中打开 `chrome://extensions` 或 `edge://extensions`。首次使用时启用开发者模式，选择「加载已解压的扩展」，选本目录的 `extension` 文件夹。
2. 本版扩展为 **0.3.8**，不新增权限，继续支持国际站和 `https://webofscience.clarivate.cn/*`。旧版用户须在扩展管理页重新加载「SA 比对半自动助手」，确认版本为 0.3.8，再刷新工作网页，重新配对 SA 并绑定两个工作页。从 0.3.1 或更早版本升级时，如浏览器要求确认 CN 网站权限，请自行核对并允许；从 0.2.x 升级还涉及 WOS 和下载权限。不获取账号/Cookie，无需删除原扩展。不要使用无法加载扩展的内置浏览器。
3. 自行登录后台，进入「SA 数据比对 → 比对结果」。助手的「连接浏览器」弹窗也有「打开后台入口」。
4. 助手点击「连接浏览器」→「复制配对码」，切到后台标签页点击扩展图标，粘贴并连接当前标签页。
5. 助手显示「浏览器已连接」后，选择任务并点击「定位网页」。每次重启助手需重新配对；切换到其他后台标签页时用「更换标签页／新配对码」。

配对码不是登录密码，不会上传；连接服务仅在你点击连接时启动。不要同时运行两个旧／新助手。只在比对结果页面工作；登录失效、查询不唯一、页面变化或编辑弹窗未关闭时会停止。网页修改后需要再次「定位网页」才能从助手重新打开编辑／认领；多条匹配必须由你在网页选择，不能猜测条目。

本版不提供自动写入平台号或网页完成状态的按钮；批准完成仍只更新本地名单。

### 「关闭只读详情超时」修复

0.3.8 针对现场复现的「根节点 DIV、直属面板 0 个、rendered=false」：若抽屉只有空的惰性占位、没有任何可见编辑或未知窗口，只在**只读定位**时重置与页面不一致的抽屉显示状态，再查询并等待真实详情面板渲染；认领和写入动作不会采用这个恢复步骤。若面板仍不出现，继续暂停，不凭空认为详情已核验。

0.3.6 修正初次打开前的空 `DIV` 占位：页面组件明确关闭、抽屉尚未渲染且没有面板时，先查询并打开详情，随后重新检查窗口归属。若抽屉的 wrapper 嵌在组件根节点内，也能按唯一窗口定位。仍须先处理任何可见编辑/确认窗口；若打开后仍没有唯一面板，程序会暂停并显示结构诊断。

0.3.5 补充兼容首次打开前的延迟渲染：仅当业务组件和窗口组件都明确关闭、且尚未渲染时，允许无 DOM；详情打开后重新验证。内部 `drawer` 引用缺失时，只在已识别窗口的自身 wrapper 内定位唯一面板，排除嵌套窗口。未知结构仍停止，报错新增根节点类型、面板数量与渲染状态，便于诊断，不包含账号或名单内容。

0.3.4 修复 SA 比对页的重复关闭流程：同一名单 ID 的只读详情保持打开，但仍重新查询列表和详情，不沿用旧数据。切换记录、收起助手查找的认领窗口、或校验完成备注时，通过对应窗口自己的关闭方法，等待关闭事件和窗口实际消失；不再等待整张网页的抽屉数量归零。

若另有人工编辑、未提交的认领选择或未知窗口，会明确提示先处理，不强关、不丢弃修改。关闭失败仍暂停，不循环重试。只读阶段超时明确显示「本次命令未提交写入」；已经发出业务写入时仍提示禁止自动重试。

升级前先自行保存或取消网页中未完成的编辑，再重新加载扩展、刷新 SA 页并配对，点「定位网页」后再执行自动化。此修复经过合成页面与实际扩展往返测试；用户现场页面连接不可用，尚未完成生产验收。

## 自动判断与 WOS 导入

1. 保留配对的 SA 比对页。另外打开已获得机构访问权限的 WOS（支持 `www.webofscience.com` 和 `webofscience.clarivate.cn` 的 HTTPS 页面）；在扩展点击「打开后台导入页面」可打开第二个后台工作页。**导入管理页就是后台左侧「数据管理 → 数据导入与批次管理」**，页面能看到「WOS数据导入(Txt)」、批次号和「推送」。普通「数据管理」列表 `#/item/entryManage` 不是导入页，目标是 `#/collectItem/batchManage`；若直达地址没有正确加载，请通过左侧菜单进入。切换到各自网页后，分别点击扩展的「绑定当前 WOS 页」「绑定当前导入管理页」。三个标签页保持打开。重新配对 SA 会清除之前的工作页绑定，需要再次绑定。
2. 选择未完成任务 → 上方「自动化」→「自动判断并执行」。程序重新查 SA：零匹配进入 WOS；未认领且编号唯一进入人员查找并预选唯一署名；通讯作者/其他字段差异打开编辑页；多匹配、编号冲突、未知字段停止。选人后仍由你确认提交认领。判断使用确定性规则，不自动把名单发给模型，不自动调用模型审批。
3. WOS 优先用入藏号，其次 DOI，否则题名检索；只对可确认的唯一结果自动打开。多结果/页面无法识别时请人工选定并核对完整记录，然后点「导出当前 WOS 文献」，它不会重做检索。
4. 导出采用 **Tab delimited + Full Record**，只捕获本次 WOS 下载的 `.txt`。必须恰好一篇、有完整表头、题名/作者/年份/WOS 号与明确交大单位署名。题名缩写、无精确编号等情况会显示证据并等待你点「继续 / 核验导入结果」确认同一成果；任何已知 DOI/WOS 冲突都不能点击确认绕过。
5. 证据明确后自动选择上海交通大学，说明为 `SA补充-<实际名单ID>`，上传、导入。随后回读确切批次的单篇题名、DOI/WOS，再按 PPT 组合查重、优先级合并、新增、本校成果设置推送。**推送可能合并已有元数据**，不会使用整体覆盖，也不操作其他批次。零匹配不证明前台绝无已有条目；发现疑似重复时先暂停核实平台号。
6. 推送回读成功后仍不会批准整条任务。请核对本库平台号、作者认领和其余差异，回人工页批准。WOS 无结果不代表未发表，也不自动标记完成。

「暂停后续步骤」在当前浏览器命令结束后阻止下一步，不能撤回已发出的上传/导入/推送。每次写入前都有本地持久记录。超时或重启后点「继续 / 核验」只核查已发出的操作，不自动再提交。上传阶段结果不明必须人工处理；不要删除日志来强制重跑。

存档在 `runtime/wos-imports/`（原始 TXT、SHA-256、单条状态/批次），不上传 Git。详见 [WOS 流程与暂停规则](IMPORT_WORKFLOW.md)。

### WOS 出错或听到异常声音

- **标题已填入，但提示 `Search / 检索 / 搜索未唯一识别`**：0.3.3 修正了图标文字混入按钮名称、无障碍标签覆盖显示文字、按钮位于条件表单外等兼容情况。只定位本文献检索区域的操作按钮，不借用导航入口或其他表单按钮；两个真实候选仍停止。新报错明确显示识别到 0 个还是多个，可点「检查工作页（只读）」复制新增按钮诊断。按钮诊断仅保留固定界面文案，任意账号/查询文案省略。模拟用例已复现旧报错，但真实页面 DOM 尚未读取，不能保证所有现场变体均已覆盖。
- **明明开了独立标签页，仍提示另开页面**：0.3.1 未支持用户截图中的 `webofscience.clarivate.cn`，且将网址不匹配和标签页重复合并提示。0.3.2 同时适配绑定、脚本权限、检索、诊断、静音和 TXT 下载；检索跳转保留当前域名，不强制返回国际站。错误提示分别说明 SA 页重复、WOS 网址不受支持、误选普通数据管理等情况，不回显登录参数。未知代理域名不会被通配放行。
- **网页显示 `Oops, something went wrong!`**：这是 WOS 的错误页面，不是本库导入窗口。旧版会误报字段选择器找不到；0.3.1 会先提示网站错误并停止。按网页提示点顶部 `Search` 或导航菜单，待正常检索页恢复再运行；持续报错时需人工检查校园网/机构访问和 WOS 登录。本程序不能修复远端服务或自动重新登录，不循环刷新、不反复提交。
- **All Fields / 所有字段**：0.3.1 增加识别；Smart Search 下会尝试通过可见的 Advanced Search → Fielded Search 进入传统字段检索，不更改账户的智能检索偏好。多行条件仍停止，不能随便取第一行。
- **不知道页面是否绑定**：在对应网页打开扩展 →「检查工作页（只读）」。显示错误页状态、当前控件和绑定类型，可选中复制反馈；不读取检索框输入、Cookie 或密码，不上传诊断到服务器。
- **声音**：程序暂停警告改为无声、非模态窗口，不再调用系统警告 MessageBox，也不会因点击被阻塞的主窗口反复提示。若声音来自网页，可在扩展点「WOS 静音 / 恢复」，只改变绑定的 WOS 标签页，不改变系统音量。静音后仍持续的声音不能归因于本程序或 WOS，需要另外定位来源。

新版检索界面变化依据：[WOS 官方 Smart Search 说明](https://webofscience.zendesk.com/hc/en-us/articles/37793163270545-July-31-2025-Release-Notes-Web-of-Science-Smart-Search-Opt-out)。

## 复制 SA 编号与自动认领

1. 人工页选择一条未完成记录并「定位网页」。程序读取**认领状态 → SA 提交**中的括号编号，如 `测试员(00001)` 提取为 `00001`；支持中英文括号，保留前导零，不使用名单 ID 代替。手动页「SA 编号」或自动化页「复制编号」可复制它。
2. 切到上方「自动化」内的「作者认领」，点「查找认领人员」；也可让「自动判断并执行」选择此路径。程序打开数据认领窗口并切到「作者认领」，在「选择作者」窗口清除姓名等筛选，按完整工号/学号搜索。此步骤不提交认领，也不会选中第一条近似结果。
3. 显示唯一人员的姓名和编号。核对下拉框中的论文作者署名：只有姓名/别名精确对应唯一作者时才预选；不能唯一对应时保持空白，由你根据证据选择。**工号准确不等于署名一定属于此人，仍须核实。**
4. 点绿色「确认并认领此作者」，再次核对弹窗中的论文、人员和署名。确认后程序重新检索，检查人员与作者数据没有变化，选择该人员并只提交一次认领，不调用网站的「批量认领」。执行期间不要同时操作网页。
5. 只有回读到对应作者行的学者 ID 正确时才显示成功，并在助手备注中加入 `已认领`。网页备注仍需你复制粘贴保存；Excel 不会因此自动变成 1。检查网页后关闭认领窗口，回人工页勾选核验并「批准完成」。

以下情况会停止，保留网页供你处理：编号缺失/多号/格式异常、名单工号冲突、多条匹配、无人员/多人员/近似号、作者归属限制、已有认领或非本人作品、人员或作者变化、登录/权限异常、未知弹窗、网络超时或回读失败。不会自动覆盖已有认领，也不执行取消认领。出现“已发出写入”时，先人工确认网站结果，**不要直接再次提交**。

查找后的临时选人窗口会自动收起，尚未绑定学者；若失败时窗口仍在，请先人工处理并关闭，再重新定位。切换任务、重新配对、打开人工编辑窗口或发生异常都会清除认领预览，避免把上一条的编号/人员带到下一条。

0.2.1 修复了「网页出现其他操作窗口，请人工处理」的一种可复现原因：网页选人窗口仍在播放关闭动画，旧版在下一次界面更新后立即检查，把它误认为陌生弹窗。新版仅等待刚刚识别的选人窗口消失，最多 5 秒；出现其他弹窗、窗口重新打开或等待超时仍停止，绝不自动关闭陌生窗口。该修复已在带动画的模拟页面和真实扩展链路中验证，尚未在用户登录的生产页面现场验证。

## WOS 导入与 PDF 补全的当前状态

WOS 单条导出、导入和推送已接入，详见上文及 [流程与验收说明](IMPORT_WORKFLOW.md)，但仍需在已登录页面完成生产首条验收。**PDF 上传暂不接入**，不要把 WOS TXT 导入当作全文补全。文献身份、人员归属、本库查重和网站授权仍需核验。

用户已明确只下载合法获取的论文 PDF 正文，不下载补充材料。WOS TXT 是文献元数据，PDF 是全文，二者不能互相代替；全文版本、使用许可和访问范围不明时停下来询问。

## 模型辅助核对

关闭旧助手后，通过原来的 `启动助手.vbs` 重开即可看到新标签页，无新增 Python 依赖。模型功能不需要改动扩展；已有网页比对资料需先在人工页「定位网页」。不定位也可以分析名单资料，但仅有名单不足以判断论文身份或批准完成。

1. 在人工页选择当前记录，定位网页，读取 SA 与本库的对比。
2. 切到「模型辅助」。默认 `deepseek-reasoner`；校方将其定位为复杂逻辑推理，因此作为本任务的默认选择，不宣称经过多模型评测是最强。可手动切换 `minimax`、`deepseek-chat`、`qwen`，不会自动换模型消耗额度。
3. 首次部署可点「密钥设置」，输入校方密钥并加密保存；本机已配置时无需重复输入。「测试连接」只查询模型列表，不发送论文或名单，不等于生成请求一定可用。
4. 必要时粘贴与当前论文有关的原文、人员姓名/别名或单位信息摘录，并写明出处。当前版本**不自动读取 PDF、截图、链接内容或进行联网检索**；仅粘贴 URL 不能证明模型已经阅读页面。
5. 点「查看发送内容」检查这一条数据，勾选发送许可，再点蓝色「辅助核对」。资料过长会明确停止，不静默截断。运行期间编辑被锁定，可点「停止等待」；已到达服务端的请求仍可能计入用量。
6. 结果列出简短结论、逐项核对、资料引用编号、待补证据和建议步骤。R1 是名单，W 开头为网页对比，E1 是手动补充证据，可在发送预览中查看。不会显示模型内部思考过程，也不把引用编号当作事实已经被独立证实。
7. 按证据自行核验并在网页处理。模型不会认领、改备注、导入、推送、上传 PDF，也不会勾选人工核验或将 Excel 写为 1。处理后仍回「人工处理」独立核验和批准。

切换记录、重新定位、编辑证据或切换模型会清除旧意见及发送许可。异步返回时再次检查名单文件与当前资料指纹，旧任务的意见不能用于新任务。意见只留在当前界面内存中，可复制，不自动写日志或保存到名单；复制意见也不等于完成备注。

### 模型与密钥保护

- 固定访问 `https://models.sjtu.edu.cn/api/v1`，使用校方 OpenAI 兼容接口；TLS 默认校验开启，不自动跟随重定向，不把密钥发往其他主机。HTTP 错误不显示响应正文，防止网关反射凭据。
- 密钥保存为 `runtime/model_api_key.dpapi`，通过 Windows DPAPI 绑定当前登录账号加密，不保存明文。换电脑或 Windows 账号后需重新配置。具备当前账号权限的程序仍可能解密，不应分享运行目录或账号。
- 模型只接收当前单条的题名/DOI/WOS/差异信息、允许的文献对比字段、手动证据和核对规则。不主动发送整份名单、负责人、名单 ID、平台 ID、浏览器令牌或 Cookie；工号等非文献字段被过滤，预览显示省略字段数；认领状态括号内的纯数字人员编号默认省略。手动证据由用户检查，勿粘贴密码等无关信息。
- 本实例串行请求，最短间隔约 6.1 秒，60 秒内最多 10 次；输入与输出均有上限。账户在其他程序的用量和每周余量由校方统一管理，界面显示的单次 tokens 不是账户剩余额度。
- 校园网或学校 VPN 才能访问。401 检查密钥，403 检查网络与授权，429 检查限流或校方额度。失败、超时、格式不合格、虚构引用或截断输出均停止，不自动重试或自动回退。
- 2026-09-23 本机已成功查询四个模型调用名；一次纯合成的真实生成请求返回 HTTP 429，已停止。因此本次验证**不包含成功的线上生成或模型判断准确率评测**，不代表密钥无效或周额度一定已用尽。

参考：[校方 API 文档](https://claw.sjtu.edu.cn/guide/sjtu-api/)。邮件中的 Qwen 版本与当前文档可能不同，界面使用 `qwen` 别名并以服务端模型列表为准，不擅自改成未授权的版本名。

## 完成标记是哪一列？

当前名单有两个名为「备注」的列：

| 列 | 本版用途 |
|---|---|
| A 列，位于负责人之前 | 完成标记。数字 1 代表已处理，隐藏于待办列表 |
| L 列，平台唯一号之后 | 原有网页备注，**不改动** |

如果今后的名单只有一个「备注」列，就使用该列；如果出现不符合上述结构的多个「备注」，程序停止，不猜测写入位置。程序按表头定位，不按固定行数套用。

- 只把真正的数字 `1`（包括数值 `1.0`）当作完成。文本 `"1"`、布尔值、其他数字或空白不会误判完成；备注公式直接提示人工检查。
- 完成状态以 Excel 为准，不用旧版日志中的「已完成」替代。因此旧日志已完成但 Excel 未标记的条目仍会出现，需要人工确认。
- 若完成备注原有文字，确认弹窗会说明将替换为数字 1；原文字保留在备份和本地日志。另一列网页备注不受影响。
- 原表数据行不删除、不移动；只从程序的待办视图中隐藏。

## 备注模板

这些是人工填写辅助；单条自动认领回读成功时会添加「已认领」，其余仍需人工判断：

- `已认领`：作者不一致、原来未认领，且你已在网页完成认领并核实保存。
- `DOI和WOSID SA未提交`：你确认 SA 的 DOI 和 WOS ID 均未提交；只缺一个时不要套用。
- `通讯作者修正`：你已按原文完成修正并确认保存。

可以合并多项并补充依据。更改文字或选择其他记录后，核验勾选会清除，需要重新人工确认。备注文字保存在本地日志；**Excel 的完成备注只写数字 1**。

## 安全回写、更新和恢复

- 回写前请**保存并关闭 Excel 中的 list.xlsx**。程序检查 Excel 占用标记、名单指纹、当前行和 ID；文件变化、被占用、备注列不明、公式或保护状态等情况会停止。
- 每次确认只改当前行一个单元格。先生成临时文件并回读，保留完整备份，再替换原文件；其他工作表、格式、公式、长编号等内容不重新生成。
- 备份位于 `runtime/backups/list-原文件指纹.xlsx`，日志在 `runtime/progress.sqlite3`。备份按内容去重，不自动删除；处理量大时注意磁盘空间。它们和原名单都不上传 Git。
- 保存失败时不显示绿色成功，不自动重试。先按提示处理，再「重读 list.xlsx」。若异常发生在替换之后，重读后以 Excel 中的数字 1 为准，不重复操作网页。
- 已修复部分空备注单元格导致的「临时文件完成标记回读失败」。现在区分空单元格的自闭合写法，并验证所有任务字段未被意外改动。请退出旧进程再重开，不要只替换文件而继续使用旧窗口。
- 更换名单：替换本目录的 `list.xlsx`，点「重读 list.xlsx」并重新选择负责人。重读会清空当前选择、未提交备注和勾选，不删除已有备份、日志。
- 如果误确认，先关闭助手，在 Excel 中核对 ID，把该条完成备注改回空白或所需原值，保存关闭后重读。原值可从备份核对；**不要随意用旧整表覆盖新名单，否则会丢失之后的进度**。
- 如果提示 `.list.xlsx.assistant.lock`，先确认所有助手实例已关闭、没有正在保存。只有确认是异常退出残留时，再移除该锁文件并重开。

不要在程序回写的同时由其他应用或脚本替换名单。文件变化检查是冲突保护，不是多人共享表格的事务服务。自动认领会校验对应关系回读，但不会替你判断论文归属，也不会验证其他手工网页修改；最终完成状态由用户审批。
